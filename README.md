# dsh-qq-conversation

DSH QQ 群聊对话调度插件。让鲸鱼接住定向发言、适量参与闲聊，并使用现有多模态能力处理缩略图。

## 功能

- **定向回应**：出现“鲸鱼”等配置别名、@机器人或引用机器人时进入定向队列；“你”等指代结合最近发言者与回复对象打分。定向回答必须引用准确的 QQ 消息 ID。
- **高频参与**：普通消息累计至少 5 条后合并参与一次，默认冷却 30 秒；不按话题分别计时。
- **低频接话**：整个群连续 30 秒没有任何新发言才可接话。任何新发言都会重置计时，已开始生成的过时接话会在发送前被拒绝。
- **有界调度**：每群一个活动批次，定向与普通队列独立；轮换作者、限制批次人数和原文总长度。新消息不取消当前模型思考。
- **可靠发送**：先保存消息与发送意图，再提交 QQ；按回执确认结果。同群发送串行，网络结果不明时不自动重发。保留待回复原文，并核对实际发送内容与身份库记忆。
- **原生图片预处理**：后台缩图到最多 512² 像素、哈希缓存、超时和并发限制；每条最多 1 图、每批最多 2 图。图片由当前 DSH 聊天模型理解，无额外视觉 API。
- **表情接口**：本地素材检索、角色与风格筛选、使用冷却、原生图片发送，以及可选 QQ 公开索引查询和素材缓存。远程候选未核验前不可发送；默认不启用远程检索，不附带鲸鱼娘素材。
- **运行维护**：off / observe / active 模式、持久化与重启恢复、只读状态查询。

## 安装要求

Node.js >=22.19；图片预处理需要 Python 和 Pillow，优先使用 DSH 附带的 Python。所选聊天模型需要原生 image 输入能力。

本版本使用 `qqConversationBridge v1`，与以下兼容包配套：

- `dsh-qq-bridge@1.0.7-conversation.1`
- `dsh-identity-vault@0.9.4-conversation.1`（v3 适配器）

主插件不内嵌整套 QQ 桥或身份库，也不在启动时改写它们的源码。原版 QQ 桥没有本插件所需接口；在现有身份库环境中，需要一起升级两个兼容包。原有 `dsh-fish-memory` 和 `billion-context` 依赖继续由身份库管理。

停止 DSH，备份当前 profile 和桥补丁审计文件，通过插件包管理流程安装配套 tgz，并启用对应组合包。不要将兼容桥替换成缺少此接口的原版；原桥更新页面的通用重装命令不适用于该兼容版本。安装后每个受管群必须绑定独立、存活的 Agent / 会话。

## 配置

将 [配置模板](examples/config.json) 复制到 `DSH_HOME/plugin-data/qq-conversation/config.json`。未设置 `DSH_HOME` 时使用用户目录下的 `.dsh`，与 QQ 桥保持一致。填写已有群绑定的 `groupIds`。配置改动会热重载，见「配置热重载」一节。

| 设置 | 含义 |
| --- | --- |
| `mode: "off"` | 默认关闭，不接收、不派发、不发送 |
| `mode: "observe"` | 观察新调度判断；原 QQ 桥仍按原规则运行 |
| `mode: "active"` | 接管选定群，替代这些群的旧 reply gate 与自动最终文本转发 |
| `scheduler` | 别名、路由阈值、整群静默时长、普通参与间隔和队列上限 |
| `nativeImages` | 图片预处理、等待上限、缓存和 Python 路径 |
| `stickers` | 本地素材目录、人设标签及使用冷却 |
| `qqStickers.enabled` | 可选 QQ 公开索引，默认 false |

默认定向阈值为 0.8，高频参与 0.65，静默接话 0.6；这些是规则分数，不是统计概率。默认定向每批最多 4 条、普通批次最多 16 条，最多 8 位作者且原文合计不超过 64,000 字符。

图片每群同时准备 1 张、全局 2 张，最多排队 24 个请求。批次默认最多等待 1.2 秒，单次准备最多 5 秒；未就绪的图片不会被当成已读内容。GIF 只取首帧，细小文字可能丢失；本版没有自动精读升级。若 Python 自动发现失败，设置 `nativeImages.python` 为包含 Pillow 的 Python 可执行文件路径。

观察转 active 前，停止宿主并归档观察期 `state.json`，避免把旧观察消息当作待回复内容。`observe` 不是机器人禁言开关。

## 配置热重载

`0.1.2` 起改 `config.json` 不用重启宿主。插件每 3 秒看一次文件指纹（`mtimeMs:size`），变了就按新配置重建 controller 顶上去，然后把旧的关掉，所以 `mode`、`groupIds`、`aliases`、`scheduler.*` 都在 3 秒内生效。

新建失败会回退——新 controller 起不来就保留旧的继续跑，只在日志里 warn。`observe` 换成 `active` 时，会把已经挂着的 agent 重新尝试挂接一遍，不用等下一轮挂载。

热重载发生在插件 `apply()` 之后，所以**装完插件本身仍然要重启一次宿主**；之后调配置就不用再重启了。

`0.1.1` 及更早版本没有这个能力，改动需要重启。补丁 `patch/host-config-hotreload.patch` 是以 `0.1.1` 未修改版为基准的 diff，本仓库里已打完，旧版本可用 `git apply` 打上。

## 状态与恢复

状态写入 `DSH_HOME/plugin-data/qq-conversation/state.json`。在插件目录执行：

```text
node bin/status.mjs <state.json的绝对路径>
```

命令只读展示队列和待核对任务。网络结果不明或重启中断的任务进入待核对状态，不能靠删除记录强制重发；明确失败最多自动尝试两轮。未决任务达到上限时暂停继续派发。

QQ 桥使用历史轮询，每次最多 200 条；断线后超出历史窗口的消息不能保证恢复。模型回合长期不结束时仍需等待。缩图减少入模数据和准备等待，不保证模型响应时间。
